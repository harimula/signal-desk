Signal Desk — how it works, end to end

A personal stock-signal website with an attached rules-based trading bot. This page explains what it does, how it is built and how it works inside, so that anyone can understand and maintain it.

Source of truth: docs/ARCHITECTURE.md in the repository. Slides: docs/architecture.pptx. Updated with every change.

Not financial advice. The website places no orders. The bot places orders only on a brokerage account whose keys its owner chose to give it.

01What Signal Desk is

WebsiteOne static page with three apps: Signal Desk (stocks), Retirement calculator, Rent vs EMI calculator. Hosted on GitHub Pages. $0.
Data refreshGitHub Actions fetches prices and news every 10–15 minutes in market hours and commits them to the repo. $0.
Trading botEvent-driven rules engine trading an Alpaca account (paper by default) during US market hours, on GitHub Actions. $0.
Research33-year backtest harness that chose the strategy; re-runnable on demand. $0.

Design principles

  • No servers to maintain. Static files plus scheduled GitHub Actions jobs.
  • No secrets anywhere public. Broker keys live only in GitHub encrypted secrets; the page never sees them.
  • No vendor lock-in. Plain Node.js with zero npm dependencies, plain HTML/JS, plain JSON. Nothing depends on Claude, Anthropic or any paid service.
  • Owner's data stays with the owner. Watchlists, portfolios, quote keys and calculator inputs live in the owner's own browser.

Prices: three freshness levels

Price updates morph the existing page instead of rebuilding it: rows never jump, scroll position never moves, and a change shows as a brief green or red flash, like a broker app.

Settings follow you (device sync)

Everything the owner sets up (Finnhub/FMP keys, proxy URL, watchlist, portfolios, custom tickers, day-trade and option amounts, theme, calculator inputs) is encrypted in the browser with the owner's passphrase (AES-256-GCM, PBKDF2 × 200 000) and saved to the owner's own repo at user/settings.enc.json. A new laptop or phone needs only the GitHub token and the passphrase, entered once in Bot settings; the rest arrives by itself. Pushes settle 8 s after a change, never more often than once a minute, and are skipped when nothing changed; pulls on load and when the tab returns; last write wins. Derived per-render data (day-trade and option logs, cached recommendations) is excluded. The token and passphrase never sync.

Responsive behaviour

  • Desktop: full tables with ‹ › arrows beside each panel to scroll wide tables.
  • Phone and tablet: full-width tables, symbols instead of company names, compact header, arrows hidden (swipe instead).
  • Dark / light toggle reaches all three apps. The page reloads itself to a newer build without losing scroll or inputs.

03Architecture

System context

Portability — no repo name in the code

Nothing in the code names a particular account or repository. The page works out which repo it belongs to from the GitHub Pages address it is served from (<owner>.github.io/<repo>/), and the bot from GITHUB_REPOSITORY, which Actions sets for the repo it runs in. A copy served from anywhere else (the claude.ai artifact) falls back to the FALLBACK_REPO constant near the top of the page script — the one line to change when the project moves. 04Technical reference

Website

  • Stack: one HTML file, vanilla JavaScript, no framework. The only external script is libsodium (to seal secrets), loaded from jsDelivr with Subresource Integrity hashes.
  • State: localStorage keys prefixed sd- (watchlist, portfolios, custom tickers, theme, refresh choice, quote keys, GitHub token, journal passphrase, calculator inputs). A setup link carries quote keys to another device.
  • Rendering: renderAll(bg). Foreground rebuilds a tab; background price ticks morph the existing DOM in place (keyed by data-s), keeping open sections, row order and scroll offsets. Scroll anchoring is off; an interaction guard delays updates while the user scrolls or types.
  • Scoring: trend (50/200-day averages), momentum, RSI, volume, distance to the chosen moving average, analyst targets and recent signals combine into a score that maps to Top Buy / Buy / Hold / Sell / Top Sell. The Rules tab lists every weight.
  • Self-update: the page polls ver.txt and reloads once when a newer build appears.

05The trading bot in depth

Why RSI-2

bot/research.mjs simulated four strategies on 39 large US stocks from 1993 to 2026, with 0.05 % costs per side, 10 % of equity per position and at most 6 positions, judged on the last 30 % of years (2016–2026), which were never used to choose anything.

StrategyOOS yearly returnOOS SharpeOOS max drawdown
RSI-2 mean reversion (chosen)+16.4 %1.45−11.9 %
Trend breakout+7.2 %0.70−13.6 %
SPY buy & hold+13.3 %0.79−34.1 %
Original intraday pullback rules (retired)−4.1 %−0.86−35.0 %

Survivorship bias flatters all rows; treat them as an upper bound. Past results do not predict future results.

Rules

  • Entries: 9:45–11:00 ET (after 10:15 on CPI/jobs days); resting limit orders at the broker.
  • Exits: take-profit +10 % (resting limit order, changeable); otherwise the last 10 minutes once the close is above the 5-day average, or after 10 sessions. A 25 % hard floor is a disaster brake and fires within a second off the stream.
  • Options: CALL at the nearest strike, 14–35 days to expiry, on the same dips; take-profit +50 % as a resting order, stop −50 %, closed 3 days before expiry. Skipped under the pattern-day-trader guard when equity is under $25 000.
  • Puts (experimental, off by default): with Trade PUT options ticked, a PUT is bought on a stock below its 200-day average whose RSI-2 is above 90 (a sharp pop in a downtrend), skipped if it has already fallen 1 %+ today. Same option rules and caps as the CALLs; exits when the stock closes below its 5-day average, after 10 sessions, or on the option take-profit / stop / expiry rules. Never backtested on options; the research workflow tests a stock-short proxy.
  • Guards: FOMC/CPI/jobs windows, live headline scan (war, White House, Fed, crisis — whole-word matching; a single company halting skips only that ticker), SPY tone; daily −3 % and weekly −6 % loss caps; 3-loss streak pause; stale orders cancelled after 45 min.

Real-time engine

Journal continuity across runs. Every run is a fresh process, and the panels the bot computes only while the market is open (watch list, market check, risk, day-trading block) plus the action log live in memory. At its first write the bot reads the previous bot/journal.json back — decrypting it with JOURNAL_KEY when it is encrypted — and carries those panels forward until it has computed fresh ones; the action log is appended to once and capped at 80 entries. A run that starts at or after 16:00 ET exits at once if today’s journal was already written at 15:55 or later; otherwise it runs one closing cycle, writes the journal and sends the day summary. A previous journal written under another passphrase is skipped with a log line, not a crash.

06Security model

  • Keys never touch the page or the repo. Bot settings seals them with GitHub's public key in the browser; only a workflow run can read them.
  • Paper and live are separate credentials. Live trading requires live mode, live keys and the typed phrase; a paper key is rejected by the live endpoint.
  • Device settings live in the public repo only as an encrypted blob under the owner's passphrase.
  • Private journal: with JOURNAL_KEY set, the journal is AES-256-GCM encrypted and numbers are scrubbed from Actions logs; the page decrypts locally with the passphrase.
  • Content-Security-Policy: the page allows only its own inline scripts (by SHA-256 hash), the hash-pinned libsodium and optional Firebase; connections only to GitHub, the price/news APIs, the relays and Firebase. tools/stamp.mjs refreshes the hashes after every edit and CI fails if they are stale.
  • Supply chain: the only third-party script is pinned by hash; Actions are pinned to commit SHAs; the bot has no npm dependencies.
  • Broker calls: 15 s deadline on every request; reads retried with backoff; order placement never retried; a cancelled run finishes its cycle and saves the journal.
  • Broker API keys can trade but cannot withdraw funds (verify in your own Alpaca settings).
  • Owner checklist (SECURITY.md): 2FA everywhere, no SMS; sole collaborator on the repo; token scoped to one repo with ≤ 90-day expiry; Telegram connected through the page only; never paste keys into chat or issues.

07Operations and runbook

First-time setup (about 20 minutes)

  1. Alpaca account → Paper → generate API keys.
  2. GitHub fine-grained token: only this repo; Contents, Secrets, Actions: read & write; 90-day expiry.
  3. Site → Bot settings: connect with the token, paste Alpaca paper keys, choose a risk profile, set a journal passphrase, Save.
  4. Repo → Actions → enable workflows; Settings → Actions → Workflow permissions → Read and write.
  5. 2FA on GitHub, Alpaca and email.

The bot starts on the next market morning. Nothing on the owner's devices needs to stay on.

Going live

Run paper for 2–3 months. Then add ALPACA_LIVE_KEY / ALPACA_LIVE_SECRET, switch Mode to Live in Bot settings and type the confirmation. Lower the risk profile first. Mind the pattern-day-trader rule (under $25 000), real slippage, overnight gaps and taxes.

08Testing and quality

  • bot/test-orders.mjs: a fake broker serves a just-dipped and a just-popped stock and the test checks the exact orders one cycle places for each CALL/PUT switch combination (puts never appear unless ticked), money limits, market scan, journal continuity across restarts, and the day-trading engine — 43 checks. Runs in CI.
  • bot/test.mjs: 77 unit tests (indicators, journal encryption round trip, signals, sizing, heat, regime, guards, journal pairing, config normalisation, RSS parsing). Runs in CI on every push.
  • Integration tests against mock brokers (REST + websocket) with a fake clock: duplicate-order prevention, take-profit timing, floor exits off streamed ticks, config hot-reload, paper↔live reconnect, PDT guard, encrypted journal and log redaction.
  • Page checks in headless Chromium at desktop and phone widths for every tab, including scroll preservation during live ticks.
  • Research and backtest workflows produce reproducible reports committed to the repo.

10Glossary

TermMeaning
RSI-22-period Relative Strength Index; below 10 marks a sharp short-term dip
SMASimple moving average, for example the 200-day
OOSOut-of-sample: years held back from strategy selection and used only to judge
CAGR / Sharpe / max DDYearly growth rate / return per unit of volatility / worst peak-to-trough loss
HeatTotal % of equity at risk across open positions and pending orders
RegimeMarket state (SPY above or below its 200-day) used to allow or block entries
PDTPattern Day Trader rule: under $25 000, at most 3 same-day round trips in 5 business days
DTEDays to expiry of an option
Paper tradingSimulated account with fake money and real prices
Sealed boxPublic-key encryption (libsodium) that stores secrets in GitHub without the browser ever reading them back
Telegram botYour private bot (made with @BotFather) that delivers alerts and answers commands
